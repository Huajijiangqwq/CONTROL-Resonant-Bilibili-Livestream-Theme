# Control Resonant · Bilibili 直播间主题

**AI 制作说明：本项目代码使用 GPT-6 Astra 生成，部分素材使用 image 生成。** 第三方代码、字体和素材单独保留来源与许可，详见 [素材与许可](docs/素材与许可.md)。

以《Control / 控制》的视觉语言为灵感，集成直播主题、弹幕特效、音乐可视化与可视化编辑器的本地桌面工具。

**1.0.2** · Windows x64 / macOS · OBS 浏览器源 · MIT / CC BY 4.0

[下载与版本](https://github.com/Huajijiangqwq/CONTROL-Resonant-Bilibili-Livestream-Theme/releases) · [使用指南](docs/使用说明.md) · [更新记录](CHANGELOG.md) · [反馈问题](https://github.com/Huajijiangqwq/CONTROL-Resonant-Bilibili-Livestream-Theme/issues)

## 四个工作区

| 工作区 | 主要用途 |
| --- | --- |
| **直播预览** | 选择布局、连接直播间、设置主播信息与计时，复制 OBS 地址。 |
| **主题编辑器** | 自由排版整个直播场景，编辑图层、组件、样式、裁剪和动画，保存与应用主题。 |
| **弹幕编辑器** | 调整弹幕区内部的字体、部件、比例与特效，支持组合容器及独立消息图层。 |
| **音乐皮肤** | 显示歌名、封面与进度，用实时音频驱动希斯流纹，调整频谱和录像质感。 |

四个页面共用界面样式，导航展开或收起的状态随页面切换保持。客户端在本机运行，无需 Codex 或在线构建服务。

## 下载与开始使用

### 选择客户端

| 系统 | 1.0.2 文件 | 使用方式 |
| --- | --- | --- |
| **Windows 10 / 11 x64** | `ControlResonant-1.0.2-win-x64.zip` | 完整解压后运行 `ControlResonant.exe`。 |
| **Mac Apple 芯片（M1 / M2 / M3 / M4 等）** | `ControlResonant-1.0.2-mac-arm64.dmg` | 打开 DMG，将 `Control Resonant.app` 拖入 Applications。 |
| **Mac Intel** | `ControlResonant-1.0.2-mac-x64.dmg` | 打开 DMG，将 `Control Resonant.app` 拖入 Applications。 |
| **源码** | `control-resonant-bilibili-theme-1.0.2.zip` | 用于开发或自行构建；普通使用请选择客户端。 |

下载入口为仓库的 [Releases](https://github.com/Huajijiangqwq/CONTROL-Resonant-Bilibili-Livestream-Theme/releases)。若所需版本尚未发布，Mac 原生构建可从 [Build macOS](https://github.com/Huajijiangqwq/CONTROL-Resonant-Bilibili-Livestream-Theme/actions/workflows/macos.yml) 中选择对应版本、提交且检查成功的记录，在页面底部的 **Artifacts** 获取：Apple 芯片选 `ControlResonant-mac-arm64`，Intel 选 `ControlResonant-mac-x64`，解压下载结果后取其中的 DMG 或 ZIP。下载 Actions 附件需要登录 GitHub，附件有保留期限。

**Mac mini M4 选择 arm64。** Mac 目标系统为 macOS 14.2+；客户端已经包含运行环境。原生 Mac 包使用临时签名（ad-hoc），尚未完成 Apple Developer ID 签名与公证，系统可能仍显示安全提示，详见 [Mac 使用说明](docs/macOS.md)。

### 接入直播与 OBS

1. 按上表安装或解压客户端并启动；Windows 请保留完整目录，不要只移动 EXE。
2. 在「直播预览 → 直播 → 弹幕接入」选择 **Bilibili 直播间**，扫码登录，填写房间号或链接后连接。
3. 选择「完整主题」「游戏优先」或「全屏分区」。主播名称、标题、布局与直播计时均可在右侧调整。
4. 点击「复制 OBS 地址」，在 OBS 添加浏览器来源，设置为 **1920 × 1080**。
5. 关闭游戏示例，将自己的游戏采集放在主题来源下方，按页面提示调整位置与尺寸。

普通使用无需安装 Node.js 或 .NET SDK。Windows 支持 Windows 10 1809+ / Windows 11 x64；按应用捕获音频建议使用 Windows 11。

关闭窗口后，本地服务仍可继续向 OBS 提供主题。结束使用时，从 Windows 托盘或 Mac 菜单栏退出；Mac 也可使用 Command-Q。客户端不会自行开始直播或录制。

### 启动问题排查

1.0.2 包含此前的启动修复：桌面界面通过内部资源地址加载，先显示界面，再初始化登录存储和本地服务，并提供启动日志与失败提示。

如果主窗口仍黑屏，请保留程序错误窗口中的信息，并按窗口所示路径查看 `desktop.log`；界面可操作时，也可从「关于与许可 → 打开数据文件夹」找到日志。反馈时附上版本、芯片、系统和本次启动对应的日志末段。主窗口加载失败与签名校验失败需分别排查，不必反复重签名。

### 更新与备份

- 更新前从托盘退出旧版，再解压运行新版本；无需把个人配置复制到程序目录。
- 同一系统账户下的设置、已保存登录、项目与已应用主题保存在独立数据目录，可从「关于与许可」打开。
- 重要主题建议导出 JSON 留档。浏览器与桌面客户端、不同本地端口的草稿可能彼此独立，迁移时用 JSON 导入导出。
- OBS 地址以当前客户端显示为准。已保存端口在后续启动时保持；更新后可刷新一次 OBS 浏览器源加载新版页面。

## 直播与弹幕

- **三种预设布局**：完整主题、游戏优先、全屏分区。全屏分区的标题备注默认隐藏，可按需开启。
- **四类消息**：普通弹幕、SC、礼物，以及舰长 / 提督 / 总督上舰提示。
- **可调提示时长**：控制停留与退场时间；分区布局支持当前有效 SC 轮播。
- **共享直播计时**：客户端与 OBS 共用计时状态，可暂停、继续、归零或设置已播时长。
- **本地消息检查**：在「消息」面板发送检查消息，确认布局与入退场效果；不会向 Bilibili 直播间发言。

扫码确认后，登录信息在当前系统账户下加密保存，重启无需重新填写。也可使用访客模式或手动填写 SESSDATA；访客用户名可能被平台打码，手动输入仅用于本次连接。详见 [扫码登录说明](docs/扫码登录.md)。

直播接入使用网页消息协议，平台鉴权、接口或风控变化可能影响连接。该项目与 Remedy Entertainment、Bilibili、OBS Project 无隶属或合作关系。

## 音乐皮肤与音频可视化

### 歌曲信息

Windows 桌面版默认通过 **SMTC** 读取播放器上报的歌名、歌手、封面和播放进度，无需另开歌曲服务。未上报信息的播放器，可切换到外部来源。

外部来源兼容 **[Widdit / now-playing-service](https://github.com/Widdit/now-playing-service)**，原作者为 **Widdit**，采用 MIT 许可。Windows 音乐页提供「自动下载并配置」：从原作者官方 GitHub 下载、校验安装器并连接，保留原程序许可。项目未预先捆绑其完整后端或安装器。核查版本、集成范围与限制见 [音乐集成说明](docs/音乐集成.md)。

### 自定义效果

| 设置位置 | 可调整内容 |
| --- | --- |
| **音频** | 桌面 / 应用音源、灵敏度、起跳速度、回落时间、高频补偿、频谱范围。 |
| **画面 → 画面质感** | 印刷质感、流纹速度、动画帧率。 |
| **画面 → 录像质感** | 总体强度、轮廓柔化、拖色宽度、基础颜色错位、动态错位、偏色强度、信号颗粒、偶发干扰频率。 |

效果设置由本机音乐服务保存，并同步到主直播页内嵌音乐及 OBS 音乐来源；内嵌音乐的帧率跟随主直播页。录像质感支持恢复默认。

**歌曲识别与音频捕获是两套独立设置。** 有歌名并不代表频谱已开启。首次使用需手动开启音频捕获；音乐皮肤会记住开关，重新打开皮肤或 OBS 来源时可恢复捕获。

独立音乐来源使用音乐页的「复制 OBS 地址」，尺寸设为 **1920 × 560**。保持客户端或托盘服务运行，缩放时锁定比例。

## 编辑与保存主题

从现有布局开始，选择组件后在右侧调整位置、尺寸、样式与动画，再保存项目或应用到直播。

- **自由画布**：支持负坐标和画布外物件；可平移、缩放、聚焦选择。框外内容可编辑，最终直播仅输出画布范围。
- **游戏窗口比例**：在「布局 → 游戏分辨率与比例」选择预设或输入自定义宽高，支持常规、超宽、方形与竖屏；使用方法见下方说明。
- **图层与组件**：添加、复制、删除、编组、锁定和调整层级；主播名称、标题备注、直播状态可独立排版，消息组件支持多实例。
- **图层样式与裁剪**：描边、内外发光、颜色叠加、投影、色调校正、模糊，以及图片 / 视频无损裁剪。样式可逐项开关、排序和比较。
- **动画预览**：调整已开放属性的关键帧和曲线，回放入场过程；本地示例与真实弹幕有明确状态提示，可随时返回实时消息。
- **项目库**：命名保存、打开、副本、重命名、JSON 导入导出及回收站恢复。

### 设置游戏窗口比例

1. 在主题编辑器的图层列表中选中 **游戏窗口**。
2. 打开右侧 **布局 → 游戏分辨率与比例**，选择预设；自定义时填写宽高，再点 **应用分辨率**。
3. 在 **变换** 中调整窗口在画布上的位置与尺寸。开启 **窗口跟随游戏比例** 时，改宽度或高度、拖动角点都会等比缩放；关闭后可独立调整宽高。
4. 点击 **应用到直播** 更新输出；需要边编辑边同步时，开启 **修改时实时应用**。

这里的“游戏分辨率”用于确定窗口比例，不会修改游戏或显示器设置，也不会改变 1920 × 1080 的主题输出画布。切换比例时以现有宽度为基准；原本位于画布内的窗口若空间不足，会等比收小。

示例图仅辅助排版，比例不同时可能留边，在 OBS 输出中自动隐藏；真实游戏画面由 OBS 采集。OBS 一键接入使用等比完整显示，采集源与窗口比例不同也可能留边。已拆出的独立外框需单独调整，或与游戏窗口编组缩放。

### 保存与应用

| 操作 | 作用 |
| --- | --- |
| **自动草稿** | 继续当前编辑进度。 |
| **保存项目** | 将主题命名留档；首次保存需要命名。 |
| **应用到直播** | 更新直播预览与固定 OBS 地址使用的主题。 |
| **修改时实时应用** | 主动开启后，后续编辑同步到直播输出。 |

保存项目不会自动替换当前直播主题。动画检查默认只在当前页面展示；需要同步到 OBS 时，再明确开启对应开关。

OBS 一键接入需要启用 OBS WebSocket，可创建或绑定受管来源，并同步主题布局和游戏采集位置。游戏仍由 OBS 采集，网页特效不能直接扭曲游戏画面。详细操作、快捷键与支持范围见 [使用指南](docs/使用说明.md)。

## 源码运行与开发

需要 **Node.js 24+** 和 npm。项目主要使用原生 JavaScript、Canvas、WebGL 与 Electron。

<details>
<summary>展开源码启动、检查与打包命令</summary>

### Windows 桌面客户端

```sh
npm install
npm run build:audio
npm start
```

音频编译使用 Windows .NET Framework 4.x 编译器，不需要 .NET SDK。

### macOS 桌面源码

```sh
npm install
npm start
```

不执行 Windows 的音频编译命令或 `.cmd` 脚本。

### 本地服务与开发检查

```sh
npm run start:server             # Windows：启动全部网页服务
npm run preview                  # 仅预览页面，不启动弹幕或音频服务
npm run dev                      # 贡献者预览，开放独立实验与录制工具
npm run check                    # 语法、资源引用与发布清洁检查
npm test                         # 本地服务与核心逻辑回归
npm run package                  # 生成源码 ZIP 与校验清单
npm run build:desktop            # Windows x64 客户端
npm run build:mac -- --arch=arm64 # 在 Mac 构建原生 Apple 芯片 ZIP / DMG
npm run build:mac -- --arch=x64   # 在 Mac 构建原生 Intel ZIP / DMG
npm run stop                     # 停止本目录启动的网页服务
```

Windows 也可使用 `启动全部服务.cmd`。纯网页服务默认使用外部歌曲来源，可在音乐页切换。`npm run dev` 只启动预览服务；详细开发入口见 [发布配置](docs/发布配置.md)。

桌面版数据位于系统用户数据目录；直接运行源码网页服务时，相关数据保存在 `app/` 和 `.runtime/` 下，均被 Git 与打包规则排除。

```text
desktop/      桌面界面、托盘与服务管理
app/          页面、编辑器、特效与本地服务
docs/         使用、架构、素材与发布说明
scripts/      启停、编译、检查与打包
tests/        回归测试
licenses/     第三方许可
```

公开客户端不含独立实验页、录制工具、构建脚本和测试文件；源码保留开发工具，普通使用无需开启。内嵌弹幕运行时与共享特效引擎始终保留。

</details>
