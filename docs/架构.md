# 代码结构与边界

这是无打包构建的浏览器应用。HTML 顺序载入原生脚本，模块多数挂在命名空间或导出 CommonJS 接口供服务与测试使用。Node.js 服务仅用内置模块；音频 FFT 的第三方实现以单文件保留。

```text
theme-editor / chat-editor
    ├─ 文档模型、样式、属性、部件、关键帧、历史记录
    └─ live.html 实时画布
          ├─ simulation：普通 / SC / 礼物 / 舰队运行时
          ├─ now-playing：歌曲排版 + 流纹 + 录像信号处理
          └─ OBS 浏览器输出 / 实时文档同步

scripts/serve.js
    ├─ preview-server：页面、主题发布、OBS 桥
    ├─ bilibili-server：网页协议 + SSE 消息
    ├─ audio-server：Windows 音频响应
    └─ now-playing-server：歌曲轮询 + 音频频谱
```

## 主要模块

| 文件族 | 职责 |
| --- | --- |
| `theme-editor-model`、`theme-scene-components`、`theme-instances` | 文档规范化、组件、多个实例与归属 |
| `theme-editor-*`、`theme-property-*`、`theme-track-*` | 编辑器界面、存储、历史、属性与轨道 |
| `theme-editor-runtime`、`theme-instance-runtime` | 文档应用到实时画布 |
| `live-*` | 原生直播页、布局、材质、音频响应 |
| `simulation`、`*-notice-engine`、`sc-*`、`fleet-*` | 消息生命周期、排版与特效 |
| `obs-bridge`、`obs-live-sync`、`theme-live-receiver` | OBS v5 连接、发布、绑定与不刷新的文档同步 |
| `now-playing-dsp`、`now-playing-spectrum240` | 48 / 240 频带、包络与音频处理 |
| `now-playing-flow-field`、`now-playing-flow-density`、`now-playing-flow-contours` | 音频流纹的运动、密度和轮廓 |
| `now-playing-signal` | 实时画面信号处理，覆盖文字、图像及频谱 |
| `audio-meter.cs`、`audio-spectrum.cs`、`now-playing-capture.cs` | WASAPI 互操作、应用 / 桌面音频捕获 |

应用文档 `format: control-theme`、`version: 1` 是数据格式版本；内部 `editorVersion` 是已有迁移记录。文档格式和迁移版本独立于应用版本号，升级至 1.0.0 不会重置旧主题的兼容记录。

## 运行边界

- OBS 原生采集显示游戏像素，网页只绘制覆盖层；两者共享场景几何信息。没有实现 OBS 视频帧输入到浏览器。
- 浏览器与服务使用本机 HTTP / SSE，OBS 使用本机 WebSocket。消息、项目与设置在本机服务之间传递。
- Windows 完整流程保留；Mac 增加独立的系统音频采集渲染进程、Music / Spotify 适配和钥匙串保护的凭据存储。Mac 包尚未实机验证，详细限制见 macOS.md。Linux 仅支持预览及逻辑测试。
- 测试中的 Fake OBS 只模拟消息请求，不能替代真实 OBS 与显卡上的兼容性验证。

## 打包

`scripts/package.js` 只从明确的源码目录和根文件收集文件，排除运行配置、发布快照、绑定、二进制编译产物和日志，生成 SHA-256 文件清单与 ZIP。历史工作目录与本包无运行依赖。

完整源码保留开发页面和测试；桌面构建使用 `runtimeEntries()` 生成精简运行内容，排除独立实验 / 录制工具及 `tests`、`scripts`、CI 文件，保留共用的内嵌消息渲染器和特效引擎。`release-profile` 同时管理本地服务可达性与打包策略，公开运行包的 `PUBLIC-RELEASE.json` 禁止开发模式。`public-dependencies` 校验清理后的实际文件闭包，见 [发布配置](发布配置.md)。
