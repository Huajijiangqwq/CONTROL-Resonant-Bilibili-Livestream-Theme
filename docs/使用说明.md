# Control Resonant 使用说明 · 1.0.1

**AI 生成说明：本项目代码使用 GPT-6 Astra 生成，部分素材使用 image 生成。**

日常使用从「直播预览」开始：选布局、接弹幕、复制 OBS 地址即可。音乐皮肤可按需要单独使用，消息检查在直播预览中完成。

客户端的四个工作区共用界面样式：直播预览、主题编辑器、弹幕编辑器、音乐皮肤。侧栏顶部箭头用于展开或收起导航，切换工作区保持同一偏好；编辑器不会再自动把整条导航切成另一种尺寸。

## 1. 启动与退出

1.0.1 已交付 Windows 客户端、Mac 应用准备包与源码。Mac 目标为 macOS 14.2+；原生 arm64 / x64 ZIP 与 DMG 按对应架构成功的 Actions 结果获取。此前的 `-setup.zip` 是交叉准备包，未完成用户设备验证及 Apple 公证。完整解压 `-setup.zip` 后，先运行随包 `修复并打开.command`，完成本机签名准备后再将 `Control Resonant.app` 放入“应用程序”。Mac mini M4 使用 arm64。步骤与限制见 [Mac 使用说明](macOS.md)。下面的 EXE 和 `.cmd` 步骤用于 Windows。

Mac 原生 ZIP / DMG 构建包含 GUI / 本地服务检查，本轮已有原生验证记录。下载前查看对应提交、架构的 Actions 状态、报告与截图；某一架构通过不能代替另一架构的结果，也不代表用户音乐、音频权限和 OBS 已通过。发布者按 [Mac 发布流程](Mac发布流程.md) 运行 GitHub Actions；原生包使用 ad-hoc 临时签名，仍不属于 Developer ID 签名或公证包。

下载桌面包后，先解压整个文件夹，再双击 `ControlResonant.exe`。程序会启动本地服务并打开直播预览，无需另装 Node.js。首次启动会选择空闲端口，后续保留；请始终使用界面复制的地址。

关闭窗口会收起到系统托盘，让 OBS 继续显示。结束使用时，在托盘选择「退出并停止本地服务」。「关于与许可」可打开使用说明、数据目录和许可文件。

使用源码时，安装 Node.js 24+ 后运行根目录的 `启动全部服务.cmd`。默认页面端口为 8791，Bilibili 接入为 8793，音频为 8794，音乐为 8795。其他端口可使用 `npm run start:server -- --port 18891` 指定。

## 2. 直播预览：选择直播布局

右侧「直播」分组中的「直播布局」提供三种常用排版：

| 布局 | 适合的画面 | 消息展示 |
| --- | --- | --- |
| 完整主题 | 保留完整品牌区和右侧通讯记录 | 各类消息在弹幕区内展示 |
| 游戏优先 | 增大游戏内容占比 | 保留较紧凑的主题与消息区域 |
| 全屏分区 | 游戏铺满画面 | 普通弹幕、SC、礼物、上舰提示分区展示 |

切到「画面」分组填写主播名称和直播标题；标题白框随文字长度调整。全屏分区默认隐藏直播标题（备注），需要时勾选「全屏分区显示直播标题（备注）」。音频响应与本地消息检查分别位于「音频」「消息」分组。

游戏示例只用于预览，实际游戏请在 OBS 中单独采集。先关闭「显示游戏示例画面」，再使用「纯画面预览」检查输出。主直播页可选择开启 Now Playing，音乐设置在侧栏「音乐皮肤」中调整。

切换布局会保留当前消息和计时。手动添加的 OBS 游戏采集需按界面显示的位置、尺寸调整；也可为不同布局分别保存 OBS 场景。

直播计时由本地服务统一保存。程序预览、编辑器和 OBS 浏览器源使用同一时钟，暂停 / 继续、归零和设置已播时长会自动同步。刷新或切换布局不会重新开始。升级后请在 OBS 刷新一次浏览器源以载入新版代码，之后无需每次刷新。此计时不控制 OBS 自身的开播或录制按钮。

直播预览的「画面来源」还可选择「编辑器 · 已应用主题」或「弹幕编辑器 · 已应用主题」。它们读取编辑器明确应用过的版本；继续修改草稿不会立刻改动直播画面。使用方法见本说明最后的编辑器章节。

编辑器输出的 OBS 主题会跟随对应通道的弹幕来源。在「主题设置 → 弹幕接入」选 Bilibili 直播间并连接后，真实消息在各输出页独立接收；同一台电脑只需连接一次房间。**编辑器和直播预览的测试消息默认只在当前页面展示。** 只有明确勾选「测试消息同步到直播 / OBS」，发送预览、混合演示、清空才会同步到输出；这些测试操作不会向 Bilibili 发送消息。编辑器打开时不自动注入示例，逐帧检查不广播。升级后刷新一次 OBS 浏览器源载入新版；首次使用已应用主题时，重新复制一次固定地址。

## 3. 弹幕接入：扫码登录与连接房间

「弹幕接入」位于直播预览右侧的「直播」分组。

1. 将消息来源切换到 Bilibili 直播间。
2. 点击「扫码登录」，使用哔哩哔哩 App 扫码并确认。确认过程由你在 App 中完成。
3. 填写房间号或直播间链接，点击连接。
4. 查看连接状态，并用实际直播间消息确认普通弹幕、礼物、SC、上舰消息是否到达。

扫码后自动获取登录信息，并在当前系统账户下加密保存；重启后无需重复填写 SESSDATA。可清除本机保存的登录。手动填写 SESSDATA 仅用于本次连接，不会自动保存；不要填写整段 Cookie。

也可选择访客模式先尝试连接，但用户名等内容可能被平台打码。本接入采用网页消息协议，平台鉴权、网络或风控变化可能影响可用性。详见 [扫码登录说明](扫码登录.md)。

## 4. 放入 OBS

日常使用已有布局不需要打开编辑器，也不要求连接 OBS WebSocket。

1. 在直播预览点击「复制 OBS 地址」。
2. 在 OBS 场景中添加「浏览器」来源，粘贴地址；完整主题设置为 **1920 × 1080**。
3. 添加自己的游戏采集，放在主题浏览器源下方。
4. 按直播预览显示的位置和尺寸调整游戏采集。全屏分区的游戏区域为 1920 × 1080。
5. 检查预览效果，再自行开始直播或录制。程序不会替你开始或停止直播、录制。

单独使用音乐皮肤时，从音乐页面复制浏览器源地址，尺寸为 **1920 × 560**。添加后可在 OBS 内等比缩放到需要的大小。

请使用 `http://127.0.0.1:…` 本地服务地址，不要勾选「本地文件」或使用 `file://`。运行 OBS 期间保留客户端或托盘服务；重开客户端后若分配地址改变，请更新浏览器源 URL。

## 5. 音乐皮肤与音频可视化

侧栏「音乐皮肤」负责歌名、歌手、封面、播放进度和希斯流纹的显示。可独立作为 OBS 来源，也可在直播预览中开启内嵌展示。

### 获取当前歌曲

macOS 源码适配读取 Music / Spotify 的公开自动化接口，系统音频入口以 macOS 14.2+ 为目标；需要系统音频与自动化权限。Spotify 封面会尝试下载，Music 暂用默认封面。Mac 暂不提供按应用选择音频及 Windows 官方安装器下载。以下 SMTC 与自动安装步骤用于 Windows。

桌面版默认使用 Windows 媒体会话（SMTC），读取播放器提供的歌曲信息。先在播放器中播放歌曲，再观察页面是否识别；播放器需支持系统媒体控制。

需要其他平台适配时，将歌曲来源切换到「外部 now-playing-service」，点击「自动下载并配置」。程序从原作者官方 GitHub 下载并校验安装器，安装后启动服务并保存连接；安装时可能需要 Windows 许可确认。已安装或已运行的服务会优先复用，也可手动填写本地服务地址，默认 `http://127.0.0.1:9863`。

**外部歌曲服务：** [now-playing-service](https://github.com/Widdit/now-playing-service)，原作者 **[Widdit](https://github.com/Widdit)**，采用 **MIT** 许可。本项目未随包捆绑其安装器或完整后端；详细来源与集成范围见 [音乐集成](音乐集成.md)。

### 让流纹跟随音乐

歌曲识别和音频捕获是两项功能。首次使用时，在音频设置开启桌面音频或指定应用的捕获，流纹才会跟随真实声音变化。音乐服务会记住捕获开关与音源；已开启时，重新打开音乐页面或 OBS 来源会恢复捕获。需要停止时请关闭音频捕获开关。

可调整灵敏度、起跳与回落。换输出设备后没有反应时，重新选择音源或停止后再开启。

帧率可选 60 FPS、30 FPS 或自定义上限；自定义最高 240。实际帧率还受 OBS、显示器、显卡及效果数量影响，性能不足时先选 30 FPS 或降低效果强度。

### 调整录像质感

打开音乐页右侧「画面 → 录像质感」，八项自定义参数均可单独调整：

| 参数 | 调整内容 |
| --- | --- |
| 总体强度 | 整体录像信号处理的强度 |
| 轮廓柔化 | 字体、图片及图形边缘的柔和程度 |
| 拖色宽度 | 色彩沿水平方向拖尾的宽度 |
| 基础颜色错位 | 持续存在的颜色偏移 |
| 动态错位 | 随时间变化的颜色错位幅度 |
| 偏色强度 | 录像色彩偏移的强度 |
| 信号颗粒 | 信号噪点的强度 |
| 偶发干扰频率 | 局部干扰事件出现的频率 |

印刷质感、流纹速度与帧率仍可分别调整。录像参数通过本机音乐服务持久保存并实时广播，音乐页、主直播内嵌音乐和 OBS 使用同一组设置，刷新或重启后继续保留。OBS 显示页读取服务设置，不会用旧链接里的参数覆盖当前设置。

## 6. 消息检查

打开直播预览右侧的「消息」面板，选择普通弹幕、SC、礼物或上舰提示，填写内容后发送一条，检查排版和入退场。这里不会向真实 Bilibili 直播间发送消息。

测试默认仅在当前预览显示；需要检查 OBS 接收时，再明确勾选测试同步。真实 Bilibili 消息与这个测试开关无关。检查后清空示例，回到真实弹幕来源。

公开版不提供独立消息实验室、组件监视录制页或 SC 档位对比页；编辑器保留制作主题需要的消息预览、动画曲线与时间轴。

## 7. 保存配置、更新与备份

界面配置保存在本机。桌面版服务数据位于应用数据目录的 `data/`，浏览器设置位于同一应用用户目录；从「关于与许可 → 打开数据文件夹」查看。更新前退出客户端，保留该数据目录，再使用新版本程序。

| 内容 | 保存方式 |
| --- | --- |
| 直播布局与页面设置 | 本机页面存储；不同浏览器、端口或客户端配置互不等同 |
| 扫码登录 | 当前系统账户的加密凭据；不随主题导出 |
| 音频、歌曲服务配置 | `audio-settings.json`、`now-playing-settings.json` |
| 自动配置的外部音乐服务 | `external-now-playing/` 内的安装及管理信息 |
| 自动草稿 | 当前浏览器的页面存储，用于继续编辑；同源编辑器之间同步 |
| 命名项目与回收站 | 本地服务数据目录的 `theme-live/project-library/`，通过项目库管理 |
| 已应用直播版本 | `theme-live/published.json`；保存命名项目不会替换它 |
| 旧版导出 / 绑定快照 | `theme-projects/`、`theme-live/` 内对应数据 |

个人设置、登录凭据、安装缓存和日志均不应上传到开源仓库，也不会进入源码打包结果。主题迁移使用 JSON 导入导出；私有素材需要自行确认后再分享。

## 8. 常见问题

### 主窗口无法打开或黑屏

1.0.1 针对 Mac 启动黑屏反馈调整了界面载入和初始化顺序，并增加分阶段日志、失败提示与有限次数的恢复。Mac 实际效果仍待反馈，尚不能确认所有黑屏的根因。

若 Mac 签名准备已经成功，优先查看程序错误窗口及其中的日志位置，保留 `desktop.log` 的本次启动记录。界面可操作时，可从「关于与许可 → 打开数据文件夹」打开。反馈附应用版本、芯片、系统版本和错误截图；不要反复重签名或先删除配置。签名准备本身失败时按 [Mac 使用说明](macOS.md) 排查。

### 直播与音乐

- **OBS 空白**：先确认客户端直播预览能打开，本地服务正在运行；检查浏览器源 URL、端口和尺寸，关闭游戏示例，确认来源没有被隐藏或挡住。必要时启用 OBS 浏览器源硬件加速并重启 OBS。
- **没有收到弹幕**：检查房间号、消息来源和连接状态；登录过期时重新扫码。连接成功不等于平台一定返回所有消息。
- **编辑器改好了，OBS 还是旧版**：查看顶部是否提示「草稿有未应用的修改」，在「应用到直播」中应用一次。确认 OBS 使用当前服务复制的固定已应用地址；仅保存项目不会改动直播。
- **编辑器测试有消息，OBS 没有**：测试默认只在画布显示。确实需要同步演示时，开启「测试消息同步到直播」；真实 Bilibili 消息不依赖此测试开关。
- **有歌名但流纹不动**：检查是否已开启音频捕获、选择了正确的音源，以及该音源是否正在发声。
- **外部歌曲服务安装失败**：确认网络能访问 GitHub；如取消了 Windows 安装确认，可重新点击「自动下载并配置」，也可从原作者发布页手动安装后填写地址。
- **端口被占用**：关闭自己的旧副本，或选择其他端口。启动程序不会强制结束占用端口的其他软件。
- **特效卡顿**：降低帧率或效果强度，减少同时显示的高强度消息，按实际 OBS 输出尺寸检查。
- **需要反馈问题**：记录操作步骤、截图、版本和错误提示，先删除其中的账号凭据或私人信息；欢迎反馈 bug 和建议。

## 9. 主题编辑器与弹幕编辑器

两个编辑器位于侧栏直播预览下方，与音乐皮肤同级排列。主题编辑器管理整个场景，弹幕编辑器调整消息区域内部效果；两者共用项目库和直播应用流程。重要项目请定期导出 JSON。

### 先分清三种保存状态

| 状态 | 用来做什么 | 会改变直播吗 |
| --- | --- | --- |
| 自动草稿 | 继续上次编辑；修改后自动保留 | 默认不会 |
| 命名项目 | 保留一个可在项目库找到、打开和导出的版本 | 不会 |
| 已应用直播版本 | 直播预览与固定 OBS 地址正在读取的主题 | 点击应用后改变；也可明确开启实时应用 |

推荐顺序：编辑草稿 → 测试画布 → 保存命名项目 → 应用到直播 → 检查 OBS。顶部的保存提示和直播版本提示分别说明两种状态，不应把「草稿已保存」当成「已更新 OBS」。

### 用项目库留档

点击「项目 → 项目库」，或左栏的文件夹按钮。首次点击顶部保存图标或按 `Ctrl/Cmd S` 时填写名称；已有命名项目时，保存会更新这个项目。想保留旧版，请选择「项目 → 另存副本」。

项目库支持名称搜索、布局示意缩略图、打开、重命名、创建副本、导出 JSON、移入回收站与恢复。选中项目后可点击「查看真实预览」，在库内播放保存版本的动效；关闭预览会释放资源，不会更改当前草稿或直播。缩略图本身仍是布局示意。「导入到项目库」只建立留档，不切换当前画布；「项目 → 导入、导出与恢复 → 导入并打开主题」会替换当前草稿，使用前先保存重要修改。

打开其他项目时先保存当前草稿；仍建议把重要修改存为命名项目。多窗口修改同一命名项目可能出现版本冲突，此时不会默默覆盖：可打开最新版本，或把当前内容另存副本。不要把草稿同步当成远程多人协作。更换电脑或重装前请导出 JSON，项目库和回收站都保存在当前电脑。

### 主题编辑器：调整整个场景

从「项目 → 从布局新建」选择完整主题、游戏优先、全屏分区或已有自定义。左栏「图层」用于选择与调整顺序，「组件」用于添加内容；右栏独立显示「布局」「样式」「动效」「全部」。选择物件后再调整参数，不需要在属性与图层之间反复滚动。底部「动画预览」按需展开，游戏窗口只提供示例，不是真实游戏采集。

「更多 → 直播与主题设置」管理共享接入、音频和计时。外侧导航按全局展开 / 收起偏好保持；切换到直播预览再返回，保留该编辑页面与撤销记录。浏览器刷新或关闭页面仍会重新载入保存的草稿。

边框通过独立部件绘制，可调整长宽比例；文字通过字号和排版宽度调整。主播名称、直播标题（备注）、直播状态已拆为独立素材，各自设置位置、字号与显隐，内容与主题设置同步。旧主题的「主播与标题」图层可点击「拆分为独立组件」，支持撤销。全屏分区的备注图层默认隐藏，点图层眼睛可恢复。

「组合弹幕区」让普通弹幕、SC、礼物、上舰提示共享区域、顺序和上下文；「独立消息图层」可将它们分别摆放。是否属于弹幕区取决于组件归属和展示方式；已有图层可以复制成多个实例。

完整输出边界固定为 **1920 × 1080**，周围是可平移的工作区。物件可以使用负坐标或拖到画面外，仍可看见、选中、编辑和保存；**框外内容不进入完整直播输出**。这适合暂放素材，或制作从画面外进入的动画。弹幕编辑器中的边框表示该弹幕容器范围。

滚轮移动视野；按住空格或中键拖动可平移；`Ctrl/Cmd + 滚轮` 围绕指针缩放。拖动物件靠近工作区边缘时，视野会继续移动。找不到物件时，选中图层后按 `F` 聚焦，或按 `Shift F` / 缩放菜单「显示全部物件」找回；按 `0` 返回输出画面。缩放工作区不会修改输出尺寸或物件坐标。

### 弹幕编辑器：调整消息区域内部

用于调整消息区域内的字体、部件、间距和特效。编辑上舰或 SC 时，注意当前修改的是组合区内的样式，还是独立消息实例。

左上「编辑范围」可切换整个场景或弹幕区内部；多个弹幕区可用下方下拉框选择。内部编辑时，工作区边界和底板操作针对当前弹幕容器，物件仍保存于同一主题场景。双击文字直接编辑，`Ctrl/Cmd Enter` 完成，`Esc` 放弃这次文字修改。

进入编辑器时默认不自动填入示例。画布底部显示当前消息状态：「真实弹幕」「本地消息」「本地示例」或「时间轴检查」；这个状态与主题是否已经应用到直播分开显示。

发送示例或拖动时间轴会进入本地检查，房间连接继续保持。检查后点击「返回实时」恢复最新真实消息；来源为本地消息时按钮显示「结束检查」。切换布局或查看存档不等于更换真实消息来源。

展开底部「动画预览」，发送预览或使用时间轴观察入场、停留、退场。关键帧只适用于已开放的属性，并非所有内部变量都能编辑。测试默认不广播；要把演示发到 OBS，必须在「应用到直播」中明确开启「测试消息同步到直播」，测试结束后关闭。

### 素材裁剪与图层样式

图片、视频和使用素材的背景可在「布局 → 裁剪」调整四边，或直接拖动原素材预览中的裁剪框。裁剪保留原文件和图层长宽，不会删除画面内容；「恢复完整素材」可随时还原。填充方式决定裁剪区域在图层框中的显示比例。此功能不处理 OBS 的游戏采集像素。

图片、视频、背景、形状和边框的「变换」提供「锁定宽高比」。开启时以当前长宽比为准，输入宽或高会联动另一边，拖动角点也保持比例；关闭后恢复独立调整。按住 Shift 拖角可以临时保持比例。裁剪改变取景，锁定宽高比改变图层框的缩放方式，两者可以一起使用。

支持的图层在「样式 → 图层样式」可添加描边、内外发光、投影、颜色叠加、色调校正和模糊，最多叠加六项，按列表顺序处理。每项可以开关、排序、重置或删除；总开关用于前后比较。描边、发光和叠色跟随内容透明度轮廓，透明图片的孔洞会保留。连续拖动一次滑块作为一次撤销。SC、上舰、礼物等消息仍使用各自的原生特效参数。渐变叠加尚未开放。

裁剪和图层样式随项目保存、JSON 导出并在应用后进入直播输出。旧项目中的效果参数继续保留。新版草稿使用独立数据版本，首次使用时读取旧草稿；不会覆盖旧版的草稿，回退时仍可找回旧记录。

### 应用主题，与直播预览和 OBS 保持一致

1. 点击顶部「应用到直播」，选择完整场景或仅组合弹幕区。仅弹幕区输出时，明确选择目标容器；隐藏或已删除的容器不能覆盖当前直播版本。
2. 点击「将当前草稿应用到直播」。应用成功后，面板显示已应用主题与修订号。
3. 复制固定 OBS 地址，粘贴到 OBS 浏览器源。完整场景为 1920 × 1080；仅弹幕区按面板提示设置尺寸。
4. 点击「查看直播」，或在主直播预览的「画面来源」中选择对应编辑器的已应用主题，核对相同版本。
5. 后续修改先留在草稿；再次应用即可更新同一固定地址，无需反复替换 URL。手动建立的 OBS 浏览器源仍需自行调整宽高；通过一键接入创建的受管来源随应用更新尺寸。

需要边改边播时，展开「实时联动与测试」，明确勾选「修改时实时应用到直播」。它与「测试消息同步到直播」是两个独立开关；不开测试同步，演示消息仍只在编辑画布内显示。多窗口同时操作时以面板的已应用修订与冲突提示为准。切换项目会停用缓存编辑器的实时应用；关闭测试广播后，尚未发出的测试队列会取消。

同一个已应用地址会跟随完整场景与仅弹幕区之间的切换。手动配置的 OBS 浏览器源仍需按新范围调整宽高；一键接入的受管来源会同步尺寸。「地址与采集信息」中可查看当前已应用版本的地址、尺寸和采集位置。

### OBS 一键接入与同步

复制固定地址不需要 WebSocket。需要自动配置场景与游戏源时，先应用一次主题，再在 OBS 开启 WebSocket 服务，在编辑器「更多 → 一键接入 OBS」连接本机 OBS，选择游戏采集来源并创建主题场景。标准 Windows 配置可自动读取，便携版可手动填写端口和密码。

默认创建的主题场景使用已应用版本的固定地址。草稿修改不会立即写到 OBS；再次「应用到直播」时，主题和受管游戏采集的几何位置一起更新。OBS 暂时断开时保留待同步状态，不阻止主题保存与应用；恢复连接后追上最新版本。面板可重试同步，或停止管理该场景而保留 OBS 中的来源。

高级选项保留旧版「草稿直接绑定」方式，需要明确开启；它与已应用版本同步分别管理。游戏依然由 OBS 采集，网页特效不能直接扭曲游戏像素。同步仅处理本程序受管场景；切换到其他场景集合时等待原集合恢复。用户替换主题来源地址后会停止接管，避免覆盖手工修改。程序不会开始、停止直播或录制，也不会自动切换节目场景。

### 常用操作

| 操作 | 快捷键 |
| --- | --- |
| 选择 / 抓手 | `V / H`；空格或中键拖动临时平移 |
| 移动 / 缩放视野 | 滚轮平移；`Ctrl/Cmd + 滚轮` 围绕指针缩放 |
| 聚焦 / 找回物件 / 回到画面 | `F` / `Shift F` / `0` |
| 撤销 / 重做 | `Ctrl/Cmd Z` / `Ctrl/Cmd Shift Z` |
| 复制 / 删除 | `Ctrl/Cmd D` / `Delete` |
| 复制到剪贴板 / 粘贴图层 | `Ctrl/Cmd C` / `Ctrl/Cmd V`；输入框中仍是文字操作 |
| 编组 / 解组 | `Ctrl/Cmd G` / `Ctrl/Cmd Shift G` |
| 微移 | 方向键 1 像素，按住 Shift 为 10 像素 |
| 图层列表导航 | 列表获得焦点后，上下方向键选择，左右展开或折叠，Home / End 首尾，F2 改名；Esc 回画布 |
| 保存命名项目 / 另存副本 | `Ctrl/Cmd S` / `Ctrl/Cmd Shift S`；草稿仍自动保存 |

图层剪贴板支持组和消息容器跨项目使用，保留相对位置、裁剪与效果参数。只在按下复制或粘贴时访问系统剪贴板，不含登录凭据和全局接入配置；单次最多 16 MB，较大内容请使用项目 JSON。浏览器不允许系统剪贴板时，复制内容仍可在当前页面的不同项目之间粘贴。

### 项目与素材容量

单个导入素材最多 8 MB，主题最多 100 个图层、每个消息样式最多 28 个内部部件；完整主题的可保存容量约 40 MB，包含内嵌素材。复制带图片或视频的物件也会增加主题文件大小。新增内容超限时保留原草稿，可先删除重复素材或换用较小文件。

较大项目导出为紧凑 JSON，仍包含素材和设置，可按正常流程重新导入。旧版留下的超限草稿可以导出救援备份，不会悄悄去掉图片；界面会明确提醒先精简素材，再重新导入或应用。自动草稿、命名项目和已应用版本仍分别保存。
