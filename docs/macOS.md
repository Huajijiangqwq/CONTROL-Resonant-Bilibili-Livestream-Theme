# macOS 下载与使用

本项目代码使用 GPT-6 Astra 生成，部分素材使用 image 生成。代码 MIT；原创文档与明确列出的原创素材 CC BY 4.0，第三方资源保留各自许可。

## 选择 1.0.2 客户端

| Mac 类型 | 推荐文件 |
| --- | --- |
| Apple 芯片（M1 / M2 / M3 / M4 等） | `ControlResonant-1.0.2-mac-arm64.dmg` |
| Intel | `ControlResonant-1.0.2-mac-x64.dmg` |

目标系统为 **macOS 14.2 及以上**。Mac mini M4 使用 arm64，在“关于本机”查看芯片与系统版本。客户端内含 Electron，无需另装 Node.js 或 Python。

从项目 [Releases](https://github.com/Huajijiangqwq/CONTROL-Resonant-Bilibili-Livestream-Theme/releases) 下载。尚未发布到 Releases 的构建，可从 [Build macOS](https://github.com/Huajijiangqwq/CONTROL-Resonant-Bilibili-Livestream-Theme/actions/workflows/macos.yml) 中选择相应版本、提交且两个架构均成功的运行记录，在 **Artifacts** 下载 `ControlResonant-mac-arm64` 或 `ControlResonant-mac-x64`。GitHub 会将附件再包成一层 ZIP，先解压，再取其中的 DMG。`Mac-verification-*` 是报告和截图，不是安装包。Actions 附件需要登录下载，且有保留期限。

## 安装与首次打开

1. 打开对应架构的 DMG，将 **Control Resonant.app** 拖入同一窗口中的 **Applications（应用程序）** 快捷方式。
2. 复制完成后推出磁盘映像，从“应用程序”启动客户端。
3. 如果下载的是原生 ZIP，完整解压后，将其中的 **Control Resonant.app** 复制到“应用程序”。

原生包在构建时完成临时签名，不需要旧版的首次修复脚本。更新前退出菜单栏中的旧程序，再替换应用；个人配置位于独立数据目录。

应用尚未完成 **Apple Developer ID 签名与公证**。临时签名（ad-hoc）不是 Apple 公证，系统仍可能提示无法验证开发者。请核对下载来源与随包 SHA-256；遇到阻止或报错时记录具体提示，不要关闭系统整体安全保护。

## 已包含的启动修复与验证

1.0.2 保留此前的主窗口资源加载、启动顺序和 Mac 签名处理修复。桌面界面通过内部资源地址加载，先显示界面，再初始化钥匙串与本地服务；失败时提供阶段日志与错误提示。

本版 Apple 芯片和 Intel 包均有云端原生构建与启动通过记录。工作流校验应用签名、DMG 完整性和挂载后的应用，再启动实际打包的客户端，检查窗口、本地服务与钥匙串初始化，并保存报告及截图。请核对所下载文件对应的提交和架构，不能用另一份包的报告代替。

这些检查不替代用户设备上的 Music / Spotify、系统音频权限、游戏采集与 OBS 联动验证。

## 启动失败或主窗口黑屏

- **系统提示损坏或无法验证开发者**：核对下载来源、架构和文件校验值，保留完整提示；不要反复使用旧版修复脚本处理新版应用。
- **程序已打开但窗口空白**：查看错误窗口中的日志路径；界面可操作时，从「关于与许可 → 打开数据文件夹」找到 `desktop.log`。
- **提交反馈**：附应用版本、Mac 芯片、macOS 版本、错误截图和本次启动对应的日志末段。分享前移除私人路径或账号信息。

签名校验、页面载入、登录存储和本地服务是不同阶段，日志用于区分失败位置。排错无需先删除项目、草稿或已保存配置。

## 日常使用

1. 启动后进入“直播预览”。右侧顶部选择弹幕来源、扫码登录并连接房间。
2. 在 OBS 添加“浏览器”来源，粘贴客户端复制的地址，大小设为 1920 × 1080。游戏采集另放在主题下方。
   直播预览和 OBS 通过同一个本地服务同步计时；在任一控制页暂停、继续、归零或修改已播时长，输出自动更新，无需重新复制地址。升级后需在 OBS 刷新一次旧浏览器源以载入新代码。此功能不自动控制 OBS 开播或录制。
3. 关闭主窗口只会隐藏窗口，本地服务继续运行。点击菜单栏倒三角图标可重新打开或完全退出；Command-Q 会退出并停止服务。
4. 登录密钥由 Electron safeStorage 通过 macOS 钥匙串保护，登录凭据以 AES-256-GCM 加密写入应用数据目录。钥匙串不可用时会禁用保存，不会退回明文保存。

## 音乐与音频

- **歌曲识别**：原生适配 Music 和 Spotify 的公开自动化接口，读取歌名、歌手、专辑与进度。请先启动播放器并播放歌曲。首次读取可能需要在“隐私与安全性 → 自动化”允许读取播放器。
- **封面**：Spotify 会尝试获取播放器提供的封面；Music 封面暂未适配，使用皮肤默认封面。这一限制不会影响歌名和进度显示。
- **系统音频**：点击页面的音频采集开关后，客户端尝试通过 Electron 的 macOS 系统音频接口传入实时 PCM，再交给现有频谱处理。首次使用需允许系统音频 / 屏幕与系统音频录制权限。权限改变后可能需要重新打开客户端。
- **采集范围**：目前是系统声音，未提供 Windows 版的按进程选择功能。采集接口附带的视频轨道只用于维持系统音频会话，不显示、不保存，也不发送给本地服务。
- **外部 Now Playing**：原作者 [Widdit](https://github.com/Widdit) 的 [now-playing-service](https://github.com/Widdit/now-playing-service) 仍保留署名与兼容接口。项目中的官方安装器自动下载功能仅用于 Windows，Mac 界面会隐藏该安装入口。

音乐识别不等于音频采集。首次使用需手动开启捕获并授予系统权限；音乐服务会记住开关状态，已开启时重新打开音乐页面或 OBS 来源会恢复捕获。需要停止时关闭捕获开关。程序不会自动开始 OBS 直播或录制。

## 从源码启动与构建

安装 Node.js 24+ 和 npm。执行 `npm install`，然后 `npm start`。Mac 不运行 `build:audio` 或 `.cmd` 启动脚本；系统采集由桌面客户端管理。

开发者打包还需要 Python 3：

```sh
npm run check
npm test
npm run build:mac -- --arch=arm64
npm run build:mac -- --arch=x64
```

构建脚本校验固定版本的官方 Electron 下载，并保留 ZIP 中 Unix 执行权限及框架符号链接。在 Mac 上构建会对 Mach-O、嵌套 app / framework 和最外层 app 从内向外做临时签名，用 `codesign` 严格验证后生成原生 ZIP 与 DMG。DMG 经过完整性检查、只读挂载与挂载后应用检查。原生分发包必须在 Mac 上构建。`--prepare-on-mac` 仅保留为贡献者的交叉准备工具，其输出需在 Mac 运行随包 `修复并打开.command`，不作为公开安装包，也不能生成原生 DMG。

源码包含可手动触发的 **Build macOS** 工作流，分别使用 `macos-15`（arm64）和 `macos-15-intel`（x64）。`scripts/smoke-mac.js` 对打包应用执行 GUI / 本地服务检查并记录截图；相应架构全部步骤通过后才上传分发包，失败时也会尝试上传已生成的诊断文件。工作流不自动发布 GitHub Release。具体启动检查结果以所选运行的报告和截图为准；CI 通过仅代表该次 runner 的窗口、钥匙串与本地服务路径通过，用户设备上的界面权限弹窗、Music / Spotify、实际系统音频和 OBS 仍需要人工实测。操作步骤与产物名称见 [Mac 发布流程](Mac发布流程.md)。

## 主题编辑器与弹幕编辑器

客户端侧栏依次为直播预览、主题编辑器、弹幕编辑器、音乐皮肤，两个编辑器与其他页面同级排列。编辑器支持项目保存、自由排版、素材裁剪、图层样式和动画曲线；自定义前请导出 JSON 备份，操作说明见《使用说明》的编辑器章节。OBS 联动效果以实际设备的采集结果为准。
