# macOS 下载、首次准备与使用

本项目代码使用 GPT-6 Astra 生成，部分素材使用 image 生成。代码 MIT；原创文档与明确列出的原创素材 CC BY 4.0，第三方资源保留各自许可。

## 当前版本与芯片选择

当前提供 **1.0.0** 的两种 Mac 应用准备包，与 Windows 版共用最新界面、编辑器及主题代码：

- **Apple 芯片（M1 / M2 / M3 / M4 等）**：`ControlResonant-1.0.0-mac-arm64-setup.zip`。
- **Intel Mac**：`ControlResonant-1.0.0-mac-x64-setup.zip`。

目标系统为 **macOS 14.2 及以上**。Mac mini M4（包括 macOS 15.8）使用 arm64。在“关于本机”中查看芯片与系统版本。已构建的运行包包含 Electron，无需另装 Node.js 或 Python；源码启动与构建要求见下文。

**本次由 Windows 交叉准备，Mac 仍待实机验证。** 两个包均以 **`-setup.zip`** 结尾，需要先在 Mac 上运行随包准备工具。随包 `BUILD-INFO.json` 如实标记 `requires-local-signing`、未公证和未实机验证；它们不是已经完成 Apple 签名的安装包。

## 首次打开

本项目暂未购买 Apple Developer ID，也未经过 Apple 公证。正式无警告分发仍需要 Developer ID 签名与公证；临时签名只用于测试。

### setup 包首次准备

请先完整解压 ZIP，不要直接双击其中尚未准备的 app。修改后的应用资源需要在 Mac 上重新生成包签名，否则可能出现“已损坏，无法打开”。这不是 M4 应下载 Intel 版的意思。

1. 核对项目来源和压缩包 SHA-256，退出已经打开的 Control Resonant。
2. 保持 `修复并打开.command`、`prepare-mac.sh` 与 **Control Resonant.app 在同一文件夹**，不要单独搬走 app。两个 setup 包已包含这些文件。
3. 双击 `修复并打开.command`。如果脚本本身被系统阻止，在终端输入 `/bin/bash `（末尾有空格），将该 command 文件拖到终端，然后按回车。
4. 工具会显示处理的应用路径。确认是本项目后输入 `YES`。它校验随包源码清单、从内向外生成本机临时签名，签名结构检查通过后，仅移除这个应用的下载隔离标记并请求打开。不会使用 sudo，也不会关闭系统 Gatekeeper。
5. 成功后可将 app 拖到“应用程序”日常使用。若失败，保留终端错误并反馈；不要对整个下载目录或系统执行移除隔离命令。

本机签名通过不代表音乐、音频权限、OBS 已测试成功。修复工具不能处理确实缺文件或校验不通过的下载包，需要重新下载。

## 日常使用

1. 启动后进入“直播预览”。右侧顶部选择弹幕来源、扫码登录并连接房间。
2. 在 OBS 添加“浏览器”来源，粘贴客户端复制的地址，大小设为 1920 × 1080。游戏采集另放在主题下方。
   直播预览和 OBS 通过同一个本地服务同步计时；在任一控制页暂停、继续、归零或修改已播时长，输出自动更新，无需重新复制地址。升级后需在 OBS 刷新一次旧浏览器源以载入新代码。此功能不自动控制 OBS 开播或录制。
3. 关闭主窗口只会隐藏窗口，本地服务继续运行。点击菜单栏倒三角图标可重新打开或完全退出；Command-Q 会退出并停止服务。
4. 登录密钥由 Electron safeStorage 通过 macOS 钥匙串保护，登录凭据以 AES-256-GCM 加密写入应用数据目录。钥匙串不可用时会禁用保存，不会退回明文保存。

## 音乐与音频

- **歌曲识别**：原生适配 Music 和 Spotify 的公开自动化接口，读取歌名、歌手、专辑与进度。请先启动播放器并播放歌曲。首次读取可能需要在“隐私与安全性 → 自动化”允许读取播放器。
- **封面**：Spotify 会尝试获取播放器提供的封面；Music 封面暂未适配，使用皮肤默认封面。这一限制不会影响歌名和进度显示。
- **系统音频**：点击页面的音频采集开关后，客户端尝试通过 Electron 的 macOS 系统音频接口传入实时 PCM，再交给现有频谱处理。首次使用需允许系统音频 / 屏幕与系统音频录制权限。权限改变后可能需要重新打开客户端。
- **采集范围**：目前是系统声音，未提供 Windows 版的按进程选择功能。采集接口附带的视频轨道只用于维持系统音频会话，不显示、不保存，也不发送给本地服务。
- **外部 Now Playing**：原作者 [Widdit](https://github.com/Widdit) 的 [now-playing-service](https://github.com/Widdit/now-playing-service) 仍保留署名与兼容接口。项目中的官方安装器自动下载功能仅用于 Windows，Mac 界面会隐藏该安装入口。

音乐识别不等于音频采集。首次使用需手动开启捕获并授予系统权限；音乐服务会记住开关状态，已开启时重新打开音乐页面或 OBS 来源会恢复捕获。需要停止时关闭捕获开关。程序不会自动开始 OBS 直播或录制。

## 从源码启动与构建

安装 Node.js 24+ 和 npm。执行 `npm install`，然后 `npm start`。Mac 不运行 `build:audio` 或 `.cmd` 启动脚本；系统采集由桌面客户端管理。

开发者打包还需要 Python 3：

```sh
npm run check
npm test
npm run build:mac -- --arch=arm64
npm run build:mac -- --arch=x64
```

构建脚本校验固定版本的官方 Electron 下载，并保留 ZIP 中 Unix 执行权限及框架符号链接。在 Mac 上构建会对 Mach-O、嵌套 app / framework 和最外层 app 从内向外签名，最后用 codesign 严格验证。Windows 上默认拒绝构建，明确指定 `--prepare-on-mac` 才会输出带本地准备工具的 setup 包，不会标为已完成签名。

仓库包含可手动触发的 **Build macOS** 工作流，分别在 Apple 芯片和 Intel macOS runner 上检查并打包。工作流产物供下载，不自动发布 Release。界面、权限弹窗、Music / Spotify、实际系统音频和 OBS 仍需要人工实测。

## 主题编辑器与弹幕编辑器

当前源码的侧栏依次为直播预览、主题编辑器、弹幕编辑器、音乐皮肤，两个编辑器与其他页面同级排列。编辑器支持项目保存、自由排版、素材裁剪、图层样式和动画曲线；自定义前请导出 JSON 备份，操作说明见《使用说明》的编辑器章节。Mac 的实际输入、渲染与 OBS 联动仍需实机确认。
